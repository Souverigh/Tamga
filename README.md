# Тамга

Распознавание и извлечение структурированных данных из кыргызских и русских
документов (паспорта, справки, договоры, банковские документы и т.д.).

Прод: https://tamga-souverigh.vercel.app

## Структура проекта

```
public/index.html   — весь фронтенд (один файл): загрузка файлов, офлайн-
                       режим (Tesseract.js, полностью в браузере) и вызов
                       Gemini-режима через собственный бекенд
api/recognize.js    — эндпоинт для веб-интерфейса Тамги (без ключа,
                       вызывается тем же сайтом)
api/v1/recognize.js — публичный API для внешних интеграций (1С и т.п.),
                       требует заголовок x-api-key
lib/recognize.js    — общая логика вызова Gemini (ключ читается только
                       из process.env.GEMINI_API_KEY на сервере)
lib/docSchema.js    — типы документов и поля извлечения (используется
                       бекендом; в public/index.html есть своя копия для
                       офлайн-эвристики Tesseract-режима)
lib/apiKeyAuth.js   — проверка x-api-key для публичного API
```

Это обычный статический сайт + Vercel Functions — фреймворк (Next.js и т.п.)
не используется, `api/*.js` подхватывается Vercel автоматически по
соглашению об именах файлов.

## Что изменилось в этой версии (ключевое)

Раньше пользователь сам вставлял свой Gemini API-ключ в браузере — ключ уходил
напрямую в Google с клиента. Теперь:

- Ключ Gemini живёт **только** в переменной окружения `GEMINI_API_KEY` на
  Vercel и никогда не передаётся в браузер.
- Режим "через Gemini" в веб-интерфейсе работает сразу, без ключа от
  пользователя — обращается к `/api/recognize` на этом же домене.
- Появился отдельный публичный API `/api/v1/recognize` для внешних систем
  (1С и подобные), защищённый ключом `x-api-key`.
- **Важно:** теперь Gemini-запросы всех посетителей сайта оплачиваются с
  вашего ключа. Это осознанное решение (SaaS-модель), но учитывайте это —
  сейчас нет лимитов на пользователя (см. «Не сделано» ниже).

## Локальная разработка

```bash
npm i -g vercel   # если ещё не установлен
cp .env.example .env
# впишите GEMINI_API_KEY и TAMGA_API_KEYS в .env
vercel dev
```

## Деплой

Проект уже привязан к Vercel-аккаунту `souverigh`, проект `tamga`.

```bash
vercel --prod
```

Либо подключите этот репозиторий к Vercel через Git-интеграцию (Project →
Settings → Git) — тогда деплой будет идти автоматически на каждый push в
основную ветку.

**Обязательно задайте переменные окружения в Vercel** (Project → Settings →
Environment Variables), иначе бекенд ответит ошибкой 500:

| Переменная       | Обязательна | Назначение                                    |
|------------------|-------------|------------------------------------------------|
| `GEMINI_API_KEY` | да          | Ключ Google AI Studio для режима Gemini        |
| `TAMGA_API_KEYS` | для API     | Ключи клиентов через запятую, для `/api/v1/*`  |

## API для интеграций

### `POST /api/v1/recognize`

```
Headers:
  Content-Type: application/json
  x-api-key: <ваш ключ из TAMGA_API_KEYS>

Body:
  { "image": "<base64>", "mimeType": "image/png" }

Response 200:
  { "documentType": "Справка", "text": "...", "fields": [{"label": "...", "value": "..."}] }
```

Поддерживаемые `mimeType`: `image/png`, `image/jpeg`, `image/webp`,
`application/pdf` (PDF передаётся Gemini целиком, без постраничной разбивки
на сервере — для многостраничных PDF это может работать хуже, чем
пословный по страницам режим в веб-интерфейсе).

Пример через curl:

```bash
base64 -w0 document.png > doc.b64
curl -X POST https://tamga-souverigh.vercel.app/api/v1/recognize \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_KEY" \
  -d "{\"image\": \"$(cat doc.b64)\", \"mimeType\": \"image/png\"}"
```

Ключи выдаются вручную — добавьте новый ключ в `TAMGA_API_KEYS` в Vercel и
поделитесь им с клиентом. Учёта запросов пока нет (см. ниже).

## Известные ограничения (осознанно, на будущее)

- **Нет учёта пользователей/лимитов.** `TAMGA_API_KEYS` — просто список
  валидных строк, без привязки к клиенту и без счётчика запросов. Это
  осознанно отложено. Когда понадобится — единственное место для замены на
  Supabase-таблицу `api_keys` (клиент, лимит, счётчик) — `lib/apiKeyAuth.js`,
  остальной код трогать не придётся. Аналогичный паттерн (Supabase +
  `SECURITY DEFINER` функция) уже используется в проекте «Хаво».
- **Нет биллинга.** Пока Gemini-запросы всех пользователей веб-сайта и всех
  держателей API-ключей идут за счёт одного `GEMINI_API_KEY` без разделения
  затрат по клиентам.
- **Лимит размера файла ~4MB** на одно изображение/страницу — это жёсткий
  лимит тела запроса serverless-функций Vercel (Hobby-план), а не
  искусственное ограничение в коде.
- **PDF в `/api/v1/recognize`** передаётся Gemini целиком, без постраничной
  разбивки (в отличие от веб-интерфейса, где PDF.js рендерит каждую
  страницу отдельно на клиенте перед отправкой).
- **Накладные/УПД, приём Excel как источника** — не реализовано, см. раздел
  «Дальнейшее развитие» в исходном хендовере (`tamga_handover.pdf`).
